## 验收约束

- NestJS 11 + Express 保持现状；提供 API 多实例与独立后台任务进程的运行方式。
- 生产禁用 schema synchronize 与测试绕过，校验独立数据库、JWT、CORS、Redis 命名空间；提供显式连接池/连接超时与可执行、可回滚迁移。
- 新数据库可迁移启动；已有开发库仅在 schema 核验无漂移后显式标记基线，禁止重建/清空数据。
- Redis 可配置认证/TLS/db/项目 key 前缀与请求超时；在线会话不得 KEYS 或全量扫描后分页。
- access/refresh token 用途隔离；多会话独立；logout/kick/冻结后不能依靠 refresh 恢复会话；TTL 与配置一致。
- 现有角色与权限变更后不能继续使用旧权限缓存；普通未封禁 IP 不应每请求回源数据库。
- 任务使用共享持久队列与独立 worker，支持重试/超时/幂等标识，验证两个实例不重复认领相同触发；记录失败、重试、完成结果。
- 区分 liveness/readiness，依赖故障不报 ready；启用优雅停机；提供结构化脱敏日志、request ID、耗时/错误/事件循环/依赖与限流指标。
- 登录/普通请求限流支持多实例共享；异常依赖、请求体、分页、批量操作有边界；公开响应不包含内部堆栈和密钥。
- 生产上传使用对象存储，提供现有 Aliyun/Tencent 适配器的明确配置和校验；本地预览仍可本地上传。
- lint 覆盖 server/shared/Admin/uni-app；添加非写入 format 检查及 CI；保留既有严格类型检查，新增代码不通过 any/ts-ignore 规避错误。
- 使用真实隔离 MySQL/Redis 做迁移、登录刷新、撤销、会话分页、限流/队列验证；报告测试环境、压测负载与局限，不承诺百万并发。
